## 15. 策略重构尝试（2026-10-19）
- **新增 `strategy/flow_rules.py`**：按 me.md 规则（连续净流入≥3、主力占比>板块中位数、超大单占比>0、5日涨幅<板块中位数、布林下轨、非ST、20日成交额>5000万、非涨跌停）。
- **新增市场择时**：沪深300（腾讯 `stock_zh_index_daily_tx`）收盘 > 200 日均线才持仓（Baostock 指数接口超时，已弃用）。
- **回测对比（2018-01-02 ~ 2026-10-19，含成本；基准=等权买入持有 3.68%）**：
  - composite top3/weekly/buffer1：年化 **0.58%**、夏普 0.18、回撤 **-70.17%**
  - composite + 择时：年化 **-2.38%**、夏普 -0.01、回撤 **-54.82%**（回撤降 15pp，但收益转负）
  - flow_rules 最优：年化 **-7.47%**（其余 -9% ~ -20%），明显更差
- **结论**：现有因子/规则在「2 板块 71 只」样本上**无法跑赢等权买入持有**；择时只降回撤、不增收益。
- **根因判断**：样本含大量小盘/ST/弱流动性标的；日频资金流信号噪声大；缺少截面中性化与仓位/波动率管理；交易成本拖累。
- **不建议继续盲目调参**。下一步先做**分年度/分 regime 的因子 IC 与分层回测**，确认信号在哪些年份/市场状态有效，再决定保留或淘汰。

## 19. 每日自动流水线（2026-10-19）

### 19.1 新增能力
- `pipeline/daily.py`：`run_daily_pipeline()` 串起 **增量 → 因子 → 信号 → 目标组合 → 模拟跟踪**。
- `pipeline/scheduler.py`：无第三方依赖的常驻调度器，工作日固定时间运行。
- CLI：
  - `python -m stock_cash_streaming.cli daily [--force] [--lookback 10]`
  - `python -m stock_cash_streaming.cli scheduler --time 16:10`
- 审计：每次运行写入 `task_log`（`task_id=daily_YYYYMMDD`），`/api/status` 可直接查看。

### 19.2 关键修复：增量覆盖全部成分
- 原 `run_incremental` 只遍历 `config/seed_members.csv` 的 **7 只**种子股，日常增量会漏掉其余 64 只。
- 已改为 **DB 成分优先**：从 `dim_sector_member` 读取全部 71 只，空库时才回退种子。
- 实测：增量目标成分 71 只，行情逐只拉取并 upsert；个股资金流快照按 71 只过滤。

### 19.3 运行逻辑
1. 非工作日且未 `--force` → `skipped`，不执行后续重计算。
2. 增量完成后检查 `MAX(fact_quote.trade_date)` 是否等于今天；不等于则 `skipped`（数据源延迟/节假日）。
3. 依次执行 `compute_all` → `generate_signals` → `build_target_portfolio(persist=True)` → `simulate_tracking(persist=True)`。
4. 任一步异常 → `failed`，异常信息写入 `task_log`，不吞错。
5. 全部成功 → `ok`。

### 19.4 调度方式
- 常驻进程：`.venv/bin/python -m stock_cash_streaming.cli scheduler --time 16:10`
  - 启动时若当天已过点且尚未成功运行，会立即补跑一次；
  - 每个进程每天最多尝试一次，失败可手动 `cli daily` 重试。
- cron 备选：
  ```cron
  10 16 * * 1-5 cd /data02/stock-cash-streaming && .venv/bin/python -m stock_cash_streaming.cli daily >> logs/daily.log 2>&1
  ```
- 时间选择：A 股 15:00 收盘，16:10 通常已有稳定的日线数据；如遇延迟，流水线会 `skipped`，可在 17:30 再补跑一次。

### 19.5 注意事项
- 增量只覆盖行情与当日资金流快照；`xl_net` 等四档历史仍依赖新浪回补（`xl_ratio_5d` 最新日会滞后，但不在防御型 8 因子权重内，不影响组合）。
- 交易日判断目前只排周末，节假日靠「行情未更新」自动跳过。
- 漏跑调仓日会导致模拟跟踪继续持有旧权重，建议保持每日运行。
- `task_log` 主键为 `daily_YYYYMMDD`，同日重跑只更新 status/ended_at/message，`started_at` 保留当天首次运行时间。

### 19.6 首次实测与关键修复（2026-10-20）

## 20. 中断恢复与运维文档（2026-10-20）

### 20.1 `cli recover`
- 新增 `pipeline/recover.py`：`run_recovery(lookback_days=30, skip_ingest=False, dry_run=False)`。
- 流程：补行情 → 全量重算因子 → 信号 → **按日期升序重放遗漏的调仓快照** → 从首个快照重放跟踪净值。
- 缺口识别：`fact_quote` 交易日序列中，`> 最后快照` 且 `i % 20 == 0` 的日期（与回测/portfolio 口径一致）。
- 安全设计：全 upsert 幂等；`--dry-run` 只读不写业务数据、也不写 `task_log`；首次无快照时只建最新日基线，不回放历史。
- 实测：`recover --dry-run` 输出「缺失调仓日：无」；`recover --no-ingest` 跑通因子/组合/跟踪，`status=ok`。

### 20.2 文档
- `docs/operations-runbook.md`：日常检查、单命令恢复、分场景处置、手工兜底步骤、校验 SQL、常见问题、备份恢复、进程重启。
- `docs/deployment-guide.md`：云服务器资源要求、Python 3.12 安装、代码/数据迁移（SQLite 在线备份拷贝）、systemd（web / daily timer / resident scheduler）、Nginx + HTTPS、防火墙、备份 cron、迁移验收清单。

### 20.3 关键运维结论
- 停机跨调仓日时，**必须重放该日快照**，否则跟踪沿用旧权重直到下个调仓日；`recover` 已自动化。
- systemd timer 的 `Persistent=true` 只能补跑一次；停机超过 1 个交易日仍需 `recover --lookback N`。
- 该架构为单机单写者：uvicorn 只能 1 worker，不能多机同时写同一 SQLite。

### 22.15 数据源修复：Baostock 挂起 → 巨潮/新浪（2026-10-26）

**现象**：本机 `baostock.query_profit_data` / `query_dividend_data` 长时间无返回，`cli universe --fundamentals` 卡死。

**根因**：Baostock 官方 `util.socketutil.send_msg` 用「末尾 13 字节是否为分隔符」判断消息结束；当响应粘包（登录响应延迟到下一次请求才被读到）或连接被关闭（`recv` 返回空）时会无限循环。裸 socket 复现证明接口本身正常（盈利/分红单次 1–2 秒返回），问题在客户端分帧逻辑。

**方案**：新增 `ingest/disclosure.py`，不再依赖 Baostock 数据接口：
- 公告日：巨潮资讯 `hisAnnouncement/query`，按「年报/半年报/一季报/三季报」分类查询，排除摘要/更正/披露提示，同一报告期取**最早正式公告日**；
- 分红：新浪「发行与分配-分红配股详情」，每 10 股口径换算为每股；
- 上市日：新浪「公司资料」页；
- 所有请求 `requests` 超时（10/25s）+ 重试 2 次；单只失败降级为法定披露截止日，不阻塞整体同步。

**回填结果**：C0∪C1∪C2∪C3 共 211 只（ETF 除外）
- 财务 96,990 行，`pub_date` 全部非空、664 个不同公告日；
- 分红 1,743 条（覆盖 201 只），`div_yield_3y` 均值 2.42%、连续性 0.81、派息率 0.79；
- `dim_stock.ipo_date` 211 只（此前为空导致 2018 年初全体被误判「上市不足 60 日」）。

**影响与验证**：C0 A0 年化由 6.74% 修正为 **6.49%**（IPO 过滤修正），B3 估值 **7.65%**；与上游 C0 6.45%/7.58% 基本一致。四池回测、`experiments --stage universes` 已重跑，`docs/experiments_universes.csv` 已更新。

**仍有限制**：历史 ST 状态仍按当前名称；财务值为新浪当前可见值，未保留历史修订链（修订表从本次回填起可追溯）。

**业务层**：
- `research/pool_admin.py`：代码规范化（换行/逗号/空格分隔、`zfill(6)`、去重）、名称解析（优先 `dim_stock`，缺失用腾讯快照，仍无法解析则要求手工填写）、池/成员 CRUD、状态计算（`data_state` / `backtest_state` / 今日 `task_log`）。

**并发**：`data/pool_job.lock` 的 `fcntl.flock` 跨进程锁，池任务（页面手动 + scheduler 每日）与 `run_daily_pipeline` 共用；抢不到锁返回 `busy`（API 409）/ `skipped`。SQLite 连接 `busy_timeout=5000`。

- 回测策略名 `defensive_top12_monthly_{pool}`；组合/跟踪 C0 仍用生产名，其它池追加 `_{pool}`。
